## 1. 文档定位

本文件用于建立一个可持续扩充的买家背景故事池，让买家私信、邮件、成交反馈和后续回访能够承载轻量叙事，并与物品组合池、万物通调查和买家推理玩法联动。

这份设计不改变现有交易规则，也不增加“回复意图”“事实/谈判/试探/隐瞒”等新按钮。玩家仍然使用现有的普通回答、核验、信任、压价和成交流程。故事信息通过买家说什么、关心什么、如何验货，以及仓库和物品资料中的细节自然出现。

### 目标

- 解决当前买家沟通内容过于单一、只像问答机器的问题。
- 让同一个买家的多次接触形成连续的小故事，而不是每一次都从零开始。
- 让物品特征、来源、标签和万物通情报能够成为故事证据。
- 为后续“买家推理”玩法提供内容，但不强迫玩家进入独立解谜界面。
- 在不增加桌面应用和窗口数量的情况下，让沟通本身承载叙事。

## 2. 与现有系统的关系

### 买家私信

私信仍然承担以下原有功能：

- 询问编号、姓名、来源、特征或价格。
- 检验玩家上架时使用的标签。
- 接受、压价、拒绝或取消交易。
- 根据信任、信誉、麻烦值和物品风险给出结果。

故事片段优先嵌入开场语、追问、成交反馈和交易后的回访中。不是每轮私信都讲剧情，也不是每件物品都触发故事。

### 邮件

邮件用于承载跨天段落，例如：

- 买家补充上一件物品的来历。
- 买家追问一段前后矛盾的时间线。
- 买家在成交后发来照片、收据或感谢信。
- 买家发现物品与自己的家族、工作或旧案有关。

邮件必须继续复用现有邮件应用和折叠列表，不创建“故事应用”。

### 物品组合池

故事不能脱离物品独立存在。每篇故事至少绑定两种可生成的内容线索，例如：

- 一个物品模板。
- 一个来源。
- 一类标签。
- 一种状态或外观破损。
- 一个可在万物通核对的特征。

### 万物通

万物通负责让玩家查证故事中的客观信息：

- 名称、编号、年份和来源是否一致。
- 同一买家是否在不同交易里提到同一人物或地点。
- 标签、票据和物品外观是否能够互相印证。
- 哪些说法是买家表面告诉玩家的，哪些是资料能够证明或否定的。

万物通不给玩家直接显示“这个买家在说谎”，只提供可比较的事实。

### 主线状态

周棠主线暂缓开发，不再作为随机买家故事的依赖或前置条件。

- 周棠、赵衡、`K-12` 和旧车站素材保留为未启用档案。
- V1.4 的叙事主体改为 3 条随机买家故事、箱子和物品图鉴。
- 买家故事不读取主线日期、证据和结局条件。
- 旧文档中所有“主线优先”“主线阶段”规则由本节覆盖。

## 3. 故事数据模型

每篇故事是一个相对完整、但在单局中分段释放的叙事单元。

```js
{
  storyId,
  buyerType,
  theme,
  trueBackground,
  publicClaim,
  fragments,
  unlockConditions,
  linkedItemTraits,
  deductionTags,
  outcomes,
  aftermath,
  mainlineBlocked,
  priority,
  repeatPolicy
}
```

### 字段说明

| 字段 | 说明 |
| --- | --- |
| `storyId` | 稳定 ID，存档和回访都依赖它，不使用随机序号 |
| `buyerType` | 适用的买家人格或固定买家类型 |
| `theme` | 故事主题，例如遗物归还、身份隐瞒、旧店倒闭、家庭债务 |
| `trueBackground` | 玩家最终有可能拼出的真实背景 |
| `publicClaim` | 买家一开始让玩家相信的表面说法 |
| `fragments` | 3 到 5 个按顺序释放的故事片段 |
| `unlockConditions` | 天数、买家信任、物品组合、故事物品和邮件状态 |
| `linkedItemTraits` | 必须由物品组合池提供的模板、来源、标签、状态或特征 |
| `deductionTags` | 可用于推理的主题，例如身份、时间、来源、关系、动机 |
| `outcomes` | 玩家正常交易或调查后可能得到的反馈 |
| `aftermath` | 结尾保留的小变化，例如回访邮件、信誉、联系人倾向 |
| `mainlineBlocked` | 旧字段，暂缓主线后仅保留迁移兼容 |
| `priority` | 与其他普通故事竞争时的权重 |
| `repeatPolicy` | 单局是否只出现一次、跨局冷却次数和允许复用的片段 |

## 4. 故事片段模型

一篇故事拆成 3 到 5 个片段。片段是实际显示在私信、邮件或成交反馈中的内容。

```js
{
  fragmentId,
  order,
  trigger,
  channel,
  text,
  attachedItemTags,
  revealedFacts,
  misleadingPoints,
  expectedInferences,
  responseMode,
  nextFragmentCondition
}
```

### 字段说明

| 字段 | 说明 |
| --- | --- |
| `fragmentId` | 故事内稳定片段 ID |
| `order` | 顺序编号，必须严格递增 |
| `trigger` | 私信轮次、成交、拒绝、次日邮件、回访或特定物品上架 |
| `channel` | 私信、邮件、成交反馈或后续回访 |
| `text` | 买家实际说出的自然语言 |
| `attachedItemTags` | 片段需要的物品组合标签 |
| `revealedFacts` | 本片段第一次明确给出的信息 |
| `misleadingPoints` | 买家的表面说法、遗漏或可被推翻的细节 |
| `expectedInferences` | 玩家理论上可以得出的结论，不直接显示给玩家 |
| `responseMode` | 沿用普通问答流程，不新增回复意图按钮 |
| `nextFragmentCondition` | 下一片段需要满足的交易、天数或调查条件 |

## 5. 拆片与推进规则

### 基本规则

- 每篇故事固定包含 3 到 5 个片段。
- 同一买家的故事片段必须按顺序释放，不能先出现结论再出现起因。
- 同一时间一名买家只能有一条进行中的故事。
- 一局中随机抽取 3 到 5 篇普通买家故事，避免所有买家同时讲长篇。
- 普通故事之间不能互相抢占同一天的关键片段。
- 玩家没有买到对应物品时，故事可以换用同主题的替代物品组合，不能给出不存在的事实。
- 玩家连续拒绝或拉黑买家时，故事可以暂停；恢复联系后再继续。

### 片段节奏

推荐节奏：

1. 片段一：一句异常但合理的闲聊，建立人物和表面说法。
2. 片段二：买家对某件物品表现出超过正常交易需求的关注。
3. 片段三：出现第一个可核对矛盾，或买家透露与物品来源有关的私人经历。
4. 片段四：成交、拒绝或万物通调查带出部分真相。
5. 片段五：回访、感谢、质问或留下下一次接触的伏笔。

短故事可以省略第四段，但不能省略前面的铺垫后直接给出真相。

### 与交易结果的关系

故事结果使用现有系统表达：

- 买家信任。
- 成交价格。
- 买家是否继续联系。
- 信誉和麻烦值。
- 商城的后续商品。
- 日历上的后续回访。

- 不新增永久、不可见的剧情数值，故事结果使用信誉、信任、价格和回访表达。

## 6. 与买家推理玩法的联动

这里的“推理”不是新的桌面应用，而是让玩家在正常沟通中逐渐发现信息不一致。

### 三类线索

1. **买家主动透露**
   - 买家会自然提到一个地点、人物、时间或物件用法。
   - 第一次出现时通常不显得关键。

2. **物品侧证据**
   - 物品模板、标签、年份、来源和破损状态能够支持或反驳买家说法。
   - 检视台负责让玩家发现表面刻印、标签残留、内部痕迹等事实。

3. **万物通交叉验证**
   - 万物通把物品事实和历史资料放在一起。
   - 相同姓名、地点、年份或交易记录会在不同查询结果中出现。

### 可推理主题

- 买家是否就是物品原主人。
- 买家是否替别人收购。
- 两个买家是否属于同一个家庭、店铺或组织。
- 物品来源时间与买家说法是否矛盾。
- 标签是后贴的，还是原包装的一部分。
- 买家为什么愿意为一类普通物品支付高价。
- 买家是在寻找物品本身，还是寻找藏在物品中的某样东西。

### 推理呈现原则

- 不在私信里显示“这是推理线索”。
- 不把正确答案直接列成三选一。
- 不添加“追问事实”“试探谎话”等独立回复意图。
- 玩家可以只完成正常交易，故事仍然成立；主动调查则能获得额外反馈。
- 推理正确后的奖励优先使用现有信誉、信任、价格、联系人邮件和后续事件。

## 7. 内容池范围

第一版建议准备 12 篇故事，每位现有买家人格对应 2 篇。后续再按玩家反馈扩充。

### 纸鹤收藏

1. **错寄的遗物**
   - 表面：买家替年迈的母亲寻找一只旧箱子。
   - 真相：箱子并不是母亲丢失的那只，但里面的标签属于母亲年轻时的同事。
   - 推理点：姓名、学校年份、旧标签和托运贴纸。

2. **修复师的女儿**
   - 表面：买家想收一只保存完好的旧银戒。
   - 真相：她继承了父亲的修复店，想找回父亲当年修复过、却被迫卖掉的物品。
   - 推理点：维修标签、工具刮痕、修复年份和店铺名称。

### 蓝账本

3. **清算公司的最后一张单**
   - 表面：买家承接公司清算，想批量低价收购。
   - 真相：其中一件物品是公司倒闭前被错误处置的员工纪念物。
   - 推理点：资产编号、清仓批次和交易日期。

4. **假账本里的真名字**
   - 表面：买家只关心利润和手续费。
   - 真相：他正在追查一本旧账本，账本里夹着能证明亲属清白的收据。
   - 推理点：手写姓名、日期、金额和万物通旧交易记录。

### 旧货狐狸

5. **替人跑腿的狐狸**
   - 表面：买家只想低价快收、快速转手。
   - 真相：他替一名不愿露面的老人回收一件被骗走的旧物。
   - 推理点：重复出现的中间人、物流单据和异常低价要求。

6. **最后一次销赃**
   - 表面：买家声称自己只做正常旧货。
   - 真相：他准备退出灰色交易，但需要确认某件物品不会连累家人。
   - 推理点：包装痕迹、真假标签和连续交易记录。

### 七号仓库

7. **无人认领的工牌**
   - 表面：仓库按批次处理遗留物品。
   - 真相：一张工牌属于多年前突然离职、并未留下地址的仓库员工。
   - 推理点：批次编号、考勤卡和员工姓名。

8. **被改写的目的地**
   - 表面：箱子只是贴错了目的地标签。
   - 真相：标签曾被替换，用来转移一批不适合公开登记的物品。
   - 推理点：新旧胶痕、航线、日期和封条状态。

### 绒布经纪人

9. **婚礼用品清单**
   - 表面：买家为拍卖会批量收购成套旧物。
   - 真相：其中一套餐具来自一场从未举行的婚礼，买家受托找回缺失的一件。
   - 推理点：餐具编号、贺卡日期和缺少的杯子。

10. **遗产拍卖的暗号**
    - 表面：买家代表多人处理遗产。
    - 真相：委托人用物品编号传递分配意愿，其中一件物品放错了箱子。
    - 推理点：编号组合、家族姓名和拍卖清单。

### 午夜电台

11. **最后一盘磁带**
    - 表面：买家想收集旧电台节目的录音带。
    - 真相：他寻找的是母亲最后一次主持节目时未播出的片段。
    - 推理点：磁带手写日期、节目单、播音员姓名和声音来源。

12. **借来的声音**
    - 表面：买家喜欢收藏旧物故事。
    - 真相：他听到的“本人录音”其实由另一个人模仿，背后是一场遗产争夺。
    - 推理点：口音、录音时间、节目档案和人物关系。

这些条目只是第一版内容种子。正式开发时需要为每篇故事写出完整片段文本、触发条件和关联物品标签。

## 8. 完整示例

### 故事：最后一盘磁带

**买家类型**：午夜电台  
**表面说法**：买家正在收集旧电台录音带。  
**真实背景**：他寻找母亲最后一次主持节目时未播出的片段。  
**关联物品**：旧收音机、录音带、手写节目单、机场行李标签。  
**推理主题**：身份、时间、家庭关系、物品来源。  
**主线关联**：无。周棠主线暂缓后，本故事独立运行。

#### 片段一：正常询价

> 这盘带子的外壳裂了没关系。  
> 我更想知道，背面手写的日期是不是原来就有的？

物品侧证据：录音带背面的日期与另一件旧收音机说明书上的节目日期相近。

#### 片段二：异常关注

> 如果箱子里还有节目单，别急着单独卖掉。  
> 有些东西放在一起，才能听出是谁在说话。

万物通可查：节目单上的主持人姓名与某位离职播音员一致。

#### 片段三：矛盾出现

> 我母亲不是主持人。  
> 我只是小时候听过她的声音，后来那盘带子被人拿走了。

物品侧证据：磁带标签上写着“最后一次试录”，不是正式节目编号。

#### 片段四：成交后的反馈

如果玩家保留节目单并如实说明来源，买家会寄来一封短邮件：

> 你留着节目单是对的。  
> 只卖磁带，谁也证明不了她来过。  
> 谢谢你把它们放在一起。

如果玩家把物品拆散出售：

- 故事仍然继续。
- 买家信任下降。
- 后续只能得到较短的结局反馈。
- 万物通仍保留可核查记录，不会因为错过片段而出现逻辑错误。

#### 结局保留

- 买家成为邮件联系人。
- 后续高价值旧音响出现时，买家可能回访。
- 万物通新增一条与旧电台节目有关的公开资料。

## 9. 随机、权重与重复控制

### 开局抽取

每局推荐抽取 3 到 5 篇普通故事：

- 不同买家人格各最多 1 篇。
- 至少 1 篇与常见物品模板有关，保证早期可触发。
- 至少 1 篇与稀有物品有关，留到中后期。
- 不与当前抽中的其他买家故事碎片同天冲突。
- 最近两局完整走完的故事降低权重。

### 单篇故事权重

故事权重可参考：

- 玩家近期搜过的物品类别。
- 玩家常用买家。
- 是否拥有符合 `linkedItemTraits` 的物品。
- 当前物品组合池中相关模板的最近出现频率。
- 该故事是否已在最近存档中出现过。

### 重复控制

- 同一局不重复释放完整故事。
- 跨局至少冷却 2 局。
- 片段文本可以复用，但必须保持一致，不能每次生成不同真相。
- 若故事未完成就结束本局，下次出现时从已解锁片段之后继续。
- 同一封关键邮件和同一天的关键事件只服务一条买家故事。

## 10. 文案原则

- 买家仍然是在交易，不是专门来向玩家讲故事。
- 每段故事都要和当前物品或上一笔交易有关。
- 不把关键信息全部藏在长段独白里。
- 一个片段只负责一到两个新信息点。
- 表面说法和真实背景都要符合人物语气。
- 角色可以隐瞒、误解或说错，但故事系统自身不能互相矛盾。
- 不写血腥猎奇内容，重点放在身份、来源、关系和选择。
- 不出现“HE”“BE”“NE”“线索等级”等破坏沉浸感的系统词。

## 11. 实现位置

### `js/data.js`

存放：

- `buyerStoryPool`
- 故事片段
- 触发条件
- 权重和冷却规则
- 角色语气模板

### `js/game.js`

负责：

- 开局抽取故事。
- 判断片段触发。
- 记录已释放片段。
- 与物品组合、买家信任、邮件和故事进度联动。
- 存档迁移时补齐缺失字段。

### `js/ui.js`

负责：

- 将片段渲染到现有私信和邮件。
- 在成交反馈中显示动作结果。
- 复用现有买家头像、折叠邮件和未读提示。
- 不新增“故事窗口”。

## 12. 第一版验收标准

- 玩家可以在不学习新按钮的情况下读完一篇故事。
- 故事片段顺序正确，刷新和读档后不会倒退。
- 同一买家的表面说法和真实背景不会互相冲突。
- 故事所需物品不存在时不会显示错误事实。
- 玩家可以把物品证据和万物通资料放在一起理解。
- 故事物品和关键词不会覆盖其他买家的故事事实。
- 私信、邮件和成交反馈之外的窗口数量不增加。
- 至少 6 篇完整故事可在一局内稳定触发。

## 13. V1.5 完整故事线规则

### 13.1 故事位与抽取

本节覆盖前文所有“每局抽取 3 至 5 篇故事”的旧规则。

- 六位买家都可以进入完整故事线。
- 最多同时推进 2 位买家。
- 其余买家进入等待展开状态，仍可正常交易，但不产生完整故事、故事物品和专属关键词。
- 只有一位进行中的故事完成后，下一位买家的故事线索才会出现。
- 每位买家只有一条主故事线，后续补充内容作为同一条故事的变体，不另开第二条主故事。
- 完成后进度写入图鉴，未完成的故事保持在当前等待或进行状态。

### 13.2 故事物品

每篇故事拥有 1 件核心物品和 2 件线索物品，共 1 至 3 件。

角色划分：

| 类型 | 数量 | 作用 | 是否必须获得 |
| --- | ---: | --- | --- |
| 核心物品 | 1 | 触发买家异常关注，解锁故事主问题 | 活跃故事保证出现 |
| 线索物品一 | 1 | 补全人物、地点或时间 | 可选，影响后续分支 |
| 线索物品二 | 1 | 提供矛盾点或隐藏结局提示 | 可选，影响后续分支 |

### 13.3 出现概率

游戏改为无限经营后，故事物品不再按固定天数窗口出现，改为按故事进度和竞拍箱数量触发。

触发条件：

- 同时最多推进 2 条买家故事。
- 每位买家完成一次普通交易后，或开局后生成 10 只箱子后，故事进入活跃状态。
- 故事物品只在对应故事进入活跃状态后开始检查。
- 概率按“每生成一只拍卖箱”计算。

标准概率：

| 物品类型 | 开始条件 | 基础概率 | 软保底 | 补偿 | 上限 | 硬保底 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 核心物品 | 故事激活后 | 10% | 8 只箱子 | 每箱 +3% | 45% | 第 12 只箱子 |
| 线索物品一 | 核心物品获得后 | 8% | 6 只箱子 | 每箱 +2% | 40% | 无 |
| 线索物品二 | 线索一获得或故事片段 3 解锁后 | 6% | 10 只箱子 | 每箱 +3% | 40% | 无 |

公式：

```text
出现概率 = min(
  上限,
  基础概率
  + max(0, 自软保底后的箱数) × 每箱补偿
)
```

限制：

- 同一只箱子最多出现一件故事物品。
- 同一件故事物品一局只出现一次。
- 只检查当前抽中的 3 条故事，不生成未抽中故事的专属物品。
- 活跃故事的核心物品最迟在第 12 只拍卖箱出现。
- 线索物品不硬保底，允许玩家错过。
- 错过线索只影响故事展示，不造成逻辑错误。
- 如果核心物品已被卖给普通买家，故事进入“错过核心”状态，买家仍可继续出现，但只能获得残缺结局。

### 13.4 关键词和万物通

只有故事关联物品才会产生可在万物通查询的关键词。

关键词来源：

- 检视时发现的手写姓名、日期、编号和来源。
- 箱子公开信息和批次编号。
- 买家对话中自然提到的地点、人物和年份。
- 成交反馈和后续回访。

查询规则：

- 便签本和万物通终端同时打开时，直接点击便签本关键词即可搜索，不需要拖动。
- 1 个关键词返回相关新闻和基础记录。
- 2 个关键词返回交叉记录、人物关系或地点时间线。
- 3 个关键词返回矛盾记录、隐藏档案或结局线索。

### 13.5 特殊选项

每条故事在第四或第五片段出现一次特殊选项。

特殊选项规则：

- 每篇故事固定预写 3 个选项。
- 选项只在故事解锁到对应片段后出现。
- 选项不显示“正确”“善良”“高风险”等系统标签。
- 选择后进入开放式结局，不显示最终真相评价。
- 已经选择过的分支写入图鉴，跨局不可回滚。

### 13.6 买家图鉴页

买家图鉴不采用箱子和物品的剪影形式，使用独立档案页。

每个买家页包含：

```text
买家头像与名称
公开身份
交易性格
故事标题
解锁进度 0 / 5
关联物品槽位 3 个
已收集关键词
已查到新闻
推论栏
特殊选项记录
开放式结局残页
```

未解锁买家显示黑头像和问号，不显示故事标题。  
已接触但未解锁故事显示买家基本信息，故事区显示“尚未进入私人话题”。  
进行中故事显示片段进度、已知信息和未确认问号。  
完成故事后保留开放式结局残页，不显示“完美结局”或“真结局”。

## 15. 图鉴和便签本的关系

关键词记录和店铺图鉴不建议强行放进同一本记事本。

原因：

- 便签本是本局调查工具，强调点击、组合和即时查询。
- 图鉴是长期收藏档案，强调浏览、进度和解锁。
- 两者放在一张页面会造成“当前线索”和“累计收集”混淆。

推荐设计：

- 关键词便签本固定在万物通终端旁边。
- 箱子、物品和买家图鉴固定在店铺档案柜上。
- 两者通过“档案钉”互相跳转。
- 当前关键词可以钉到某个物品或买家页上，显示为本局临时标记。
- 图鉴页可以显示“本局有相关线索”，点击后翻到便签本对应页。

这样既保留两个系统的不同节奏，又不会生硬合并。

### 15.1 图鉴全收集奖励

箱子和物品采用最简单的图鉴形式：

- 已经见过的箱子或物品直接显示完整条目。
- 尚未见过的箱子或物品显示黑色剪影。
- 不显示稀有度、爆率、利润提示或系统评价。

每个图鉴全收集的奖励只作为彩蛋存在：

- 奖励一件没有属性、没有收益、不能出售的特殊摆件。
- 摆件可以放在店铺指定位置，例如柜台、书架、窗台和后间。
- 奖励内容包括小型雕像、旧海报、纪念章、盆栽和旧收音机摆件。
- 不提供价格加成、信誉加成、买家信任或任何经济收益。
- 图鉴完成度只影响店铺外观和档案页装饰。

买家图鉴不采用剪影规则。买家页以头像、关系和故事进度展示，完成后的开放式结局作为独立残页保存。

## 17. V1.5 验收标准

- 六位买家都可以进入完整故事线。
- 最多同时推进 2 位买家。
- 一位故事完成后，下一位买家的故事线索才会出现。
- 每条故事包含 1 件核心物品和 2 件可选线索物品。
- 核心物品最迟在第 12 只拍卖箱出现。
- 线索物品按窗口概率出现，允许错过。
- 普通物品不会产生故事关键词。
- 只有故事物品和买家对话能产生可查询词条。
- 便签本和万物通同时打开时，点击关键词即可查询。
- 每条故事固定预写 3 个特殊选项。
- 特殊选项选择后进入开放式结局，不显示最终答案。
- 买家图鉴分别显示买家信息、进度、物品槽、关键词、新闻和推论。
- 箱子和物品图鉴使用已见显示、未见解锁剪影。
- 全收集奖励只提供无属性摆件、装饰和视觉彩蛋。
- 周棠主线不作为随机买家故事依赖，也不影响无限经营节奏。
